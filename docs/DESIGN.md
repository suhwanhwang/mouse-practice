# 마우스 섬 모험 상세 문서

Sep 26, 2026 · @Suhwan Hwang

## 개요

마우스 섬 모험은 아이패드 터치에만 익숙한 초등학교 2학년 아이가 마우스 조작을 게임처럼 익히는 웹사이트다. 섬 8개, 단계 24개를 차례로 깨면서 이동부터 스크롤까지 배우고, 마지막 섬에서 가짜 컴퓨터 화면으로 모든 기술을 함께 써 본다.

- **대상**: 글을 막 읽기 시작한 초등 저학년. 모든 안내는 짧은 한국어 문장과 음성으로 나온다.
- **목표**: 학교 컴퓨터 수업에서 필요한 여섯 가지 조작(이동, 가리키기, 클릭, 더블클릭, 오른쪽 클릭, 끌어서 놓기, 스크롤)을 혼자 할 수 있게 하기.
- **환경**: 마우스가 연결된 컴퓨터의 최신 브라우저. 아이패드에 마우스를 연결해도 된다.
- **저장**: 진행 기록은 그 브라우저에만 저장되고 서버는 없다.
- **주소**: https://shwang.dev/mouse-practice/ (블로그 커스텀 도메인 아래 하위 경로)

한 판은 레벨당 1\~2분 안에 끝나도록 맞췄다. 한 번에 섬 한두 개씩, 15\~20분 정도 하는 사용을 가정했다.

## 섬별 상세

섬마다 조작 하나를 집중해서 연습하고, 단계가 올라갈수록 목표물이 작아지거나 빨라지거나 많아진다. 섬 3단계를 모두 끝내면 스티커 하나를 받고 다음 섬이 열린다.

한 단계는 여러 **판**으로 이어진다. 기본은 3판이고, 더 연습이 필요한 풍선 축제(클릭), 병아리 농장(더블클릭), 동물 마을(끌어서 놓기)은 2판을 더해 5판, 한 판이 긴 보물 컴퓨터는 2판이다. 판이 끝날 때마다 화면 가운데 "2 / 5" 표시가 뜨고, 풍선과 알은 판마다 8%씩(최대 30%) 작아진다. 아래 표의 개수는 한 판 기준이고, 병아리 농장 1단계라면 알 4개 × 5판 = 더블클릭 20번이다.

| 섬 | 배우는 것 | 1단계 | 2단계 | 3단계 | 스티커 |
| --- | --- | --- | --- | --- | --- |
| 1 마우스 친구 만나기 | 잡는 법, 움직이기 | 잡는 법 그림 안내 후 커서를 5,000px 움직이면 별 꼬리가 따라옴 | 화면에 흩어진 별 6개(110px)에 화살표를 올려 모으기 | 나비 옆 90px 안에 화살표를 두고 8초 따라가기. 놓치면 나비가 천천히 기다려 줌 | 나비 |
| 2 비눕방울 공원 | 가리키기 | 비눕방울 8개, 140px, 초속 45px | 12개, 105px, 초속 70px | 16개, 80px, 초속 100px | 폭귄 |
| 3 풍선 축제 | 왼쪽 클릭 | 가만히 있는 풍선 8개(120px) 터뜨리기 | 올라가는 풍선 12개(105px) | 두더지 잡기 12번. 두더지가 나와 있는 시간이 2.8초에서 1.5초로 줄어듦 | 사자 |
| 4 병아리 농장 | 더블클릭 | 알 4개(150px) 톡톡 눌러 부화 | 알 6개(120px) | 알 8개(95px) | 병아리 |
| 5 선물 가게 | 오른쪽 클릭 | 선물 3개. 오른쪽 클릭 메뉴에 열기 하나만 있음 | 선물 4개. 메뉴 3개(열기, 색칠하기, 리본 달기) 중 열기 찾기 | 선물 5개. 선물 위에 적힌 말과 같은 메뉴 고르기 | 곰돌이 |
| 6 동물 마을 | 끌어서 놓기 | 동물 4마리를 같은 그림이 붙은 집으로 | 과일 8개를 종류별 바구니 4개로 | 4조각 퍼즐. 흐린 밑그림을 보고 맞추기 | 강아지 |
| 7 바닷속 탐험 | 스크롤 | 화면 4개 깊이, 맨 아래 보물 누르기 | 화면 5개, 숨은 바다 친구 5마리 찾기 | 화면 6개, 보물을 들고 다시 올라와 배 누르기 | 문어 |
| 8 보물 컴퓨터 | 모두 함께 | 폴더 더블클릭 → 창에서 스크롤 → 보물 파일 더블클릭 | 쓰레기 4개를 휴지통으로 끌기 → 휴지통 오른쪽 클릭 → 비우기 | 폴더 열기 → 스크롤로 열쇠 찾기 → 열쇠를 보물 상자로 끌기 → 상자 오른쪽 클릭 → 열기 | 유니콘 |

크기는 목표물 지름, 속도는 초당 픽셀이다. 모든 수치는 `src/games/` 안 각 게임 파일의 `byLevel(...)` 값으로 바꿀 수 있다.

### 섬마다 다르게 처리하는 점

- **풍선 축제**: 오른쪽이나 가운데 버튼을 누르면 왼쪽 버튼이 깜빡이는 마우스 그림이 뜨고 "왼쪽 버튼으로 눌러요"라고 알려 준다. 빈 곳을 누르면 실수 하나로 센다.
- **병아리 농장**: 첫 클릭에 알이 흔들리고 "톡!" 글자와 함께 주황색 링이 퍼져 나간다. 링이 사라지기 전에 한 번 더 누르면 부화한다. 링이 다 사라질 때까지 기다리면 "한 번 더 빨리! 톡톡!"이라고 알려 준다.
- **선물 가게**: 왼쪽 클릭하면 오른쪽 버튼이 깜빡이는 그림을 보여 준다. 틀린 메뉴를 골라도 그 효과(색 바꾸기, 리본)는 일어나지만 완료로 치지 않는다. 맥에서 Ctrl+클릭으로 메뉴를 열어도 실수로 세지 않는다.
- **동물 마을**: 누르고 바로 떼면 "꾹 누른 채로 끌어야 해요!"라고 알려 준다. 틀린 자리에 놓으면 물건이 제자리로 돌아간다.
- **바닷속 탐험**: 스크롤 막대를 숨겨서 휠을 쓰도록 유도한다. 오른쪽의 깊이 막대에 잠수부가 현재 위치를 보여 준다. 맥의 자연스러운 스크롤 설정에서는 방향이 반대라서 안내는 "바퀴를 굴려요"로만 하고 방향은 말하지 않는다.
- **보물 컴퓨터**: 실제 바탕화면처럼 아이콘을 한 번 누르면 선택되고, 두 번 누르면 열린다. 오른쪽 위 체크리스트가 지금 할 일을 주황색으로 표시한다.

이 밖에 지도 화면의 **그림판**은 언제든 쓸 수 있다. 색 8개, 붓 굵기 3가지, 지우개가 있고 끌어서 그리므로 드래그 연습도 된다.

## 학습 설계 원칙

아이가 글을 읽지 않아도, 틀려도 좌절하지 않고 끝까지 갈 수 있게 하는 것이 기준이다.

- **읽기보다 듣기**: 마스코트 생쥐 "마루"가 말풍선으로 안내하고, 같은 문장을 브라우저 한국어 음성(속도 0.95, 높이 1.15)으로 읽는다. 마루 얼굴이나 스피커 버튼을 누르면 다시 들려준다.
- **실패 없음**: 틀리면 부드러운 "뿡" 소리와 흔들림만 있고 게임이 끝나지 않는다. 놓친 비눕방울이나 풍선은 다시 나온다.
- **힌트**: 연속으로 3번 틀리면 마루가 그 단계의 힌트 문장을 말하고, 게임이 다음 목표물에 점선 테두리를 표시하거나 손가락 시범을 보여 준다. 한 번 맞히면 연속 실수 수는 0으로 돌아간다.
- **점점 어렵게**: 1단계는 목표물이 크고(120\~150px) 느리고, 단계가 올라갈수록 작아지고 빨라진다. 두더지 게임은 한 판 안에서도 잡을수록 빨라진다.
- **즉각 보상**: 성공할 때마다 효과음, 반짝이 조각, "팡!" 같은 떠오르는 글자가 나온다. 연속으로 맞히면 효과음 음이 한 칸씩 올라간다. 머리글 오른쪽의 점(또는 막대)이 남은 양을 보여 준다.

### 별 계산

단계를 끝내면 그 판의 실수 횟수로 별을 준다. 끝까지 하면 최소 1개는 받는다.

| 실수 횟수 | 별 |
| --- | --- |
| 0\~2 | 3개 |
| 3\~6 | 2개 |
| 7 이상 | 1개 |

실수로 세는 것은 빈 곳 클릭, 틀린 버튼, 틀린 자리에 놓기, 틀린 메뉴, 놓친 목표물이다. 같은 단계를 다시 하면 더 좋은 기록만 남는다.

### 잠금 해제

- 첫 섬은 처음부터 열려 있다.
- 섬 안에서는 앞 단계를 별 1개 이상으로 끝내야 다음 단계가 열린다.
- 섬 3단계를 모두 끝내면 스티커를 받고 다음 섬이 열린다.
- 부모 설정의 **모든 섬 열기**를 켜면 순서와 상관없이 고를 수 있다.

## 부모 가이드

처음 한두 번은 옆에서 마우스 잡는 손을 봐 주고, 그다음부터는 아이 혼자 섬을 골라 하게 두면 된다.

### 사용 순서

1. 시작 화면에서 **시작하기**를 누른다. 브라우저는 첫 클릭 뒤부터 소리를 낼 수 있어서, 이 버튼이 소리를 켜는 역할도 한다.
2. 지도에서 반짝이는 섬을 누르고 단계를 고른다.
3. 마루의 안내를 듣고 놀이를 끝내면 결과창에서 다시 하기, 다음 단계, 지도 중 하나를 고른다.
4. 모은 스티커는 지도 아래 **스티커 도감**에서 볼 수 있다.

### 부모 설정

지도 화면 왼쪽 위 **마우스 섬** 로고를 3초 동안 누르고 있으면 열린다. 주소 끝에 `#/parent`를 붙여서 바로 열 수도 있다. 아이가 실수로 들어가지 않게 만든 장치이고, 암호는 없다.

| 항목 | 기본값 | 선택지 | 언제 바꾸나 |
| --- | --- | --- | --- |
| 음성 안내 | 켜짐 | 켜기 / 끄기 | 조용한 곳에서 할 때 |
| 효과음 크기 | 0.7 | 0\~1 | 소리가 크거나 작을 때 |
| 더블클릭 인식 간격 | 0.7초 | 1초 / 0.7초 / 0.5초 | 아이가 병아리 농장에서 계속 막히면 1초로, 익숙해지면 0.5초(실제 컴퓨터와 비슷)로 |
| 휴식 알림 | 20분마다 | 끄기 / 15 / 20 / 30분 | 화면을 보고 있는 시간만 센다. 알림이 뜨면 30초 뒤에 다시 놀기 버튼이 켜진다 |
| 모든 섬 열기 | 꺼짐 | 켜기 / 끄기 | 아이가 어려워하는 조작만 골라 연습할 때 |
| 진행 기록 지우기 | - | 두 번 눌러야 지워짐 | 다른 아이가 처음부터 할 때 |
| 한 단계 길이 | 보통(3판) | 짧게 1판 / 보통 3판 / 길게 5판 | 금방 끝난다면 길게, 지겹어하면 짧게. 클릭·더블클릭·끌기 섬은 여기에 2판을 더한다(짧게일 때는 제외) |

### 함께할 때 팁

- 마우스는 아이 손에 맞는 작은 것이 좋다. 마우스 패드를 깔면 커서가 덜 튀다.
- 이동과 클릭이 섞이는 것이 가장 흔한 실수다. 누를 때는 손목을 멈추고 손가락만 움직이도록 알려 준다.
- 더블클릭과 끌어서 놓기가 가장 어렵다. 병아리 농장과 동물 마을은 별 3개가 나올 때까지 며칠에 걸쳐 반복해도 좋다.
- 터치로 누르면 "마우스를 연결해 주세요" 안내가 한 번 나온다. 아이패드를 쓸 때는 블루투스 마우스를 연결하면 된다.
- 기록은 브라우저별로 저장된다. 다른 컴퓨터나 시크릿 창에서는 처음부터 시작한다. 이때는 모든 섬 열기를 켜면 바로 이어서 할 수 있다.

## 기술 구조

Vite 8 + TypeScript로 만든 정적 웹사이트이고, 프레임워크도 서버도 없다. 그림은 이모지와 CSS·SVG, 효과음은 Web Audio 합성, 음성은 브라우저 Web Speech API라서 외부 에셋 파일이 하나도 없다. 빌드 결과는 JS 48KB(gzip 19KB), CSS 18KB다.

| 경로 | 역할 |
| --- | --- |

| `src/ui/` | 화면: 시작, 지도, 놀이 틀(play), 결과창, 스티커 도감, 그림판, 부모 설정, 마스코트 |

### 화면 흐름

주소의 해시가 화면을 정한다. `#/`(시작) → `#/map`(지도) → `#/play/섬/단계` → 결과창 → 다음 단계나 지도로 간다. 그 밖에 `#/stickers`, `#/draw`, `#/parent`가 있다. 화면이 바뀔 때마다 `Lifetime` 객체가 그 화면의 이벤트 리스너, 타이머, 애니메이션 루프를 한 번에 정리해서 새는 것이 없다.

### Game 인터페이스

각 게임은 함수 하나다. 놀이 틀이 `GameContext`를 넘겨 주고, 게임은 선택적으로 `hint()`를 돌려준다. 결과창, 별 계산, 저장, 힌트 시점은 모두 놀이 틀(`src/ui/play.ts`)이 처리하므로 게임 쪽은 놀이만 신경 쓰면 된다.

```ts
interface GameContext {
  root: HTMLElement;   // 게임을 그리는 영역
  level: number;       // 0, 1, 2
  round: number;       // 이번 판 번호(0부터)
  lt: Lifetime;        // 리스너·타이머 자동 정리
  settings: Settings;
  say(text: string): void;              // 말풍선 + 음성
  miss(quiet?: boolean): void;          // 실수 1회, 3연속이면 힌트
  progress(done: number, total: number): void;
  win(): void;
}
type Game = (ctx: GameContext) => { hint?: () => void } | void;
```

새 섬을 추가하려면 `src/games/`에 게임 함수를 만들고, `src/games/index.ts`의 `GAMES`와 `src/data/stages.ts`의 `STAGES`에 같은 순서로 한 줄씩 넣는다.

### 핵심 모듈

| 모듈 | 하는 일 | 설계상 포인트 |
| --- | --- | --- |
| `core/storage.ts` | 별 기록과 설정을 localStorage에 저장, 잠금 해제 판단 | 저장이 막힌 시크릿 창에서는 메모리에만 저장. 깨진 데이터는 기본값으로 복구. `version` 필드로 형식 변경 대비 |
| `core/input.ts` | 더블클릭 판정기, 드래그 도우미 | 더블클릭은 브라우저 기본값 대신 간격(설정값)과 거리(30px)를 직접 판정. 드래그는 6px 이상 움직여야 시작하고, 복제본이 포인터를 따라다니다가 실패하면 제자리로 돌아감 |
| `core/menu.ts` | 가짜 오른쪽 클릭 메뉴 | 큰 글씨, 화면 밖으로 나가지 않게 위치 보정, 바깥을 누르면 닫힘 |
| `core/audio.ts` | 효과음 10종 합성 | 오실레이터로 즉석 생성, 음량은 설정 따름 |
| `core/speech.ts` | 한국어 음성 안내 | 이모지와 따옴표는 읽지 않음. 한국어 음성이 없으면 조용히 생략 |
| `core/fx.ts` | 반짝이 조각, 떠오르는 글자, 색종이 | Web Animations API 사용, 끝나면 요소 제거 |
| `core/random.ts` | 목표물을 겹치지 않게 흩어 놓기 | 자리가 모자라면 간격을 조금씩 줄여 다시 시도 |

## 개발·테스트·배포

단위 테스트 15개가 모두 통과하고 타입 검사와 빌드도 오류 없이 끝난다. 배포는 `main` 브랜치에 푸시하면 자동으로 된다.

### 명령어

| 명령 | 하는 일 |
| --- | --- |
| `npm install` | 의존성 설치(Node 22 이상) |
| `npm run dev` | 개발 서버. http://localhost:5173/mouse-practice/ |
| `npm test` | vitest 단위 테스트 |
| `npm run build` | 타입 검사 후 `dist/`에 정적 파일 생성 |
| `npm run preview` | 빌드 결과를 배포 경로(`/mouse-practice/`) 그대로 미리보기 |

### 단위 테스트 범위

- **저장**: 깨진 데이터 복구, 새 설정 항목 채우기, 더 좋은 기록만 남기기, 단계·섬 잠금 해제 순서, 모든 섬 열기.
- **더블클릭 판정**: 간격 안의 두 클릭, 느린 두 번째 클릭, 너무 멀리 움직인 클릭, 세 번째 클릭이 또 더블클릭이 되지 않는지.
- **그 밖**: 난이도 값 고르기, 별 계산, 목표물 흩어 놓기(겹침·경계), 주소 해석, 음성에서 이모지 빼기.

### 브라우저 검증(Chrome)

실제 마우스 동작으로 시작 → 지도 → 단계 완료 → 결과창, 더블클릭 부화, 오른쪽 클릭 메뉴, 끌어서 놓기, 휠 스크롤, 보물 컴퓨터 미션 전체를 확인했다. 이 과정에서 찾은 문제 네 가지를 고쳤다.

| 문제 | 수정 |
| --- | --- |
| 잡는 법 그림의 손이 거꾸로 있음 | 손가락이 버튼 쪽을 향하도록 바로잡음 |
| 선물 색이 위의 글씨표까지 물듦 | 색을 상자 그림에만 입힘 |
| 숨어 있는 두더지 귀가 보임 | 구멍 모양을 다시 그리고 완전히 가림 |
| 힌트 테두리가 긴 줄에서 빙글빙글 돎 | 돌지 않고 깜빡이도록 바꿈 |

### GitHub Pages 배포

1. 변경 사항을 커밋하고 `main`에 푸시한다.
2. 저장소 Settings → Pages → Source를 **GitHub Actions**로 한 번 바꾼다.
3. Actions가 설치 → 테스트 → 빌드 → 배포를 차례로 한다. 테스트가 실패하면 배포하지 않는다.
4. 배포가 끝나면 https://shwang.dev/mouse-practice/ 에서 열린다.

저장소 이름을 바꾸면 `vite.config.ts`의 `base`도 같이 바꿔야 한다.

## 알려진 한계와 다음 할 일

가장 먼저 할 일은 아이가 직접 해 보고 막히는 곳에 맞춰 난이도와 음성 속도를 조정하는 것이다.

### 아직 확인하지 못한 것

- 비눕방울, 반딧불, 나비, 올라가는 풍선처럼 프레임마다 움직이는 놀이는 자동화 브라우저 탭이 백그라운드로 잡혀 화면에서 움직이는 것은 못 봤다. 움직임이 필요 없는 별 꼬리 단계는 완료까지 확인했다.
- 음성 안내는 테스트할 때 꺼 두어서 실제 발음과 속도를 들어 보지 못했다. macOS는 Yuna, Windows는 Heami 등 설치된 한국어 음성에 따라 다르게 들릴 수 있다.
- Safari와 Windows Chrome에서는 아직 해 보지 않았다.

### 알려진 한계

- 진행 기록이 브라우저에만 있어서 기기를 바꾸면 이어지지 않는다.
- 화면 크기를 판이 시작할 때 한 번만 재서 목표물을 놓는다. 놀이 중에 창 크기를 바꾸면 배치가 어긋날 수 있다. 이때는 다시 하기를 누르면 된다.
- 보물 컴퓨터는 윈도우와 맥을 섮은 단순한 모양이라 학교 컴퓨터 화면과는 다를 수 있다.
- 키보드 연습과 화면 읽기 프로그램 지원은 범위에 넣지 않았다.
